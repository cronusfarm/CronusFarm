# CronusFarm 설정·MQTT·DB 스키마 (초안)

`nodered/settings-tab-roadmap.txt` 의 **설정 탭 전면 재설계** 전에 MQTT·저장소 형식을 고정하기 위한 작업 문서다.  
구현과 불일치하면 **본 문서를 우선 수정**하고 펌웨어·Node-RED를 맞춘다.

---

## 1. 현행 MQTT 토픽 (DEVICE_ID 예: `cronusfarm-01`)

| 방향 | 토픽 패턴 | QoS·retain 비고 |
|------|-----------|-----------------|
| Pi → Arduino 명령 | `cronusfarm/{DEVICE_ID}/cmd` | Arduino 구독 |
| Arduino → Pi 텔레메트리 | `cronusfarm/{DEVICE_ID}/tele` | 문자열 한 덩어리 |
| Arduino LWT/연결 | `cronusfarm/{DEVICE_ID}/status` | `online` / `offline` |
| Pi SSID 동기(프로젝트 설정) | `secrets`/빌드에 정의된 토픽 | Arduino 추가 구독 |

## 2. 현행 `tele` 문자열 (Arduino 조립)

한 줄(또는 연속 문자열). 구간은 ` | ` 로 구분한다.

| 구간 | 접두 | 의미 |
|------|------|------|
| `S:` | 스위치/출력 읽기값 | `채널키=0|1` 공백 구분. 원격 채널은 내부 상태 반영 |
| `A:` | 채널별 AUTO | `채널키=0|1` (1=AUTO) |
| `T:` | 펌프 주기(초) | 펌프 채널만 `키=on초/off초` |
| `W:` | WiFi | `ssid=… ip=a.b.c.d` (미연결 시 placeholder) |
| `G:` | 펌프 하드 가드 상태 | **펌프 채널만**. 문법은 아래 §2.1 |

**채널 키 (`CH_KEY`)** — 펌웨어와 동일한 문자열만 유효하다.

`led_a1`, `led_a2`, `led_b1`, `led_b2`,
`pump_a1`, `pump_a2`, `pump_b1`, `pump_b2`,
`fan_a1`, `fan_a2`, `fan_b1`, `fan_b2`,  
`pump_c1`, `pump_c2`, `pump_d1`, `pump_d2`

### 2.1 시간 상수 용어 (펌프 가드)

스케줄의 `on_채널`·`off_채널`(주기 초)과 **이름이 비슷해 혼동하기 쉬우므로** 아래 용어로 구분한다. 값은 모두 **펌웨어 상수(초)**.

| 용어 | 기호 (예시) | 정의 |
|------|-------------|------|
| **최대 연속 ON 초** | `T_max_on` | 한 채널 출력이 **OFF 없이 연속으로 HIGH인 시간**의 상한(초). 이 시간을 **넘기 전에** 반드시 OFF 되어야 하며, 넘기면 가드가 **즉시 OFF(트립)** 후 쿨다운으로 들어간다. MQTT 주기의 ON 길이와 별개이며, 주기가 길어도 **연속 ON 누적**은 이 상한에서 끊긴다. |
| **쿨다운 초** | `T_cool` | **최대 연속 ON 초과 트립**이 발생한 뒤, 그 채널을 **다시 ON으로 올릴 수 없게 유지하는** 최소 시간(초). 경과 후에는 합의대로 **AUTO/주기 로직에 따라 자동 재개** 가능. |
| **최소 OFF 초** | `T_min_off` | 한 번 ON 구간이 끝난 뒤(OFF로 전환 후), **다음 ON을 허용하기 전**에 OFF가 유지되어야 하는 최소 시간(초). 짧은 주기로 ON/OFF가 반복되는 **쇼트사이클**을 막는다. 스케줄의 `off_채널`(주기 OFF 길이)과 다르다: 스케줄 OFF가 짧으면 가드가 **다음 ON 시점을 밀어** `T_min_off`를 채우게 할 수 있다. |

### 2.2 `tele` 가드 구간 `G:` 문법 (합의)

- **위치**: 기존 구간 뒤에 ` | ` 로 붙인다. 권장 순서는 `S` → `A` → `T` → `W` → `G` (각 구간은 `S:…` 형태로 앞에 나열한 뒤 ` | ` 로 연결).
- **대상 채널**: `pump_a1` … `pump_d2` **펌프만** `G:` 에 등장한다. LED/FAN은 넣지 않는다.
- **토큰**: `G:` 다음 **공백 한 칸으로 구분**하는 항목들. 각 항목 형식은 다음 중 하나다.  
  - `ok` — **모든 펌프**가 가드에 의해 금지 상태가 아님(간편 표기).  
  - `<펌프키>=<코드>` — 해당 채널만 비정상·대기 상태.  
  - `<펌프키>=<코드>/<정수>` — 남은 시간(초)을 함께 표시할 때. `<정수>`는 **남은 쿨다운 초** 또는 **남은 최소 OFF 대기 초**에 사용(코드별로 의미 고정).

**상태 코드 (`<코드>`)**

| 코드 | 의미 |
|------|------|
| `ok` | 해당 채널: 가드로 인한 출력 금지 없음. |
| `mx` | **Max-on 트립**: 연속 ON 한도(`T_max_on`) 초과로 강제 OFF된 뒤 **쿨다운 중**. `pump_a1=mx/42` → 쿨다운 **남은 42초**. |
| `mf` | **Min-off 대기**: `T_min_off`를 아직 채우지 않아 **다음 ON 불가**. `pump_a1=mf/15` → 최소 OFF 충족까지 **남은 15초**. |

**동시성 (합의)**: 같은 채널에 `mx`와 `mf`가 **동시에** 걸리는 경우는 **없다**. `tele`에도 채널당 코드는 **하나만** 보내면 된다.

**권장 패턴 (페이로드 길이)**

- 모든 펌프가 정상이면 **`G:ok`** 한 토큰만 보낸다.  
- 하나라도 비정상이면 **`G:` 에는 비정상 채널만** `pump_x=mx/…` · `pump_y=mf/…` 형태로 나열하고, 정상 펌프는 생략한다(파서는 “없으면 ok”로 해석).

**구현 시 할 일**

1. **Arduino** — `CronusFarm.ino`: 매 루프 `pumpGuardLoop`, `publishTelemetry()` 에 ` | G:…` 조립 **반영됨**.  
2. **Node-RED / 대시보드** — `fn_tele_guard_ui` + `tele 펌프 가드 G:` 위젯(`flows_cronusfarm_dashboard.json`). `flow.lastTeleG`·`flow.lastTeleGWarn` 저장. 구 tele(G 없음) 호환.  
3. 상수는 아래 표와 `CronusFarm.ino` 매크로 동기화.

### 펌웨어 상수·저장 (구현 기준)

| 용어 | 값 | 코드 (`CronusFarm.ino`) |
|------|-----|-------------------------|
| `T_max_on` | 1800 s (30분) | `PUMP_GUARD_MAX_ON_MS` |
| `T_cool` | 60 s | `PUMP_GUARD_COOLDOWN_MS` |
| `T_min_off` | 10 s | `PUMP_GUARD_MIN_OFF_MS` |

**EEPROM(UNO R4)** `[200..233]`: 매직 `0xC3`·버전 `1`, 펌프 8개 각각 **mx 쿨다운 잔여 초·mf 잔여 초**(각 `uint16` LE). 트립 시 즉시 저장, 그 외 **약 120초마다** 갱신. 재부팅 시 잔여 시간을 로드해 mx/mf 보수적 복원(연속 ON 누적은 부팅 시 펌프 OFF 정책으로 RAM에서 새로 쌓음).

## 3. 현행 `cmd` 페이로드 (Arduino 파서)

- **최대 길이**: 펌웨어 수신 버퍼 **약 160바이트** (확장 시 펌웨어와 함께 상향 필요).
- **형식 1**: 레거시 단일 문자 — 현재 `applySingleCharCmd` 는 **노오프**, 실질적으로 **key=value 권장**.
- **형식 2**: 공백으로 구분된 `key=value` 토큰 연속.

### 3.1 지원 키 (요약)

| 키 패턴 | 예시 | 의미 |
|---------|------|------|
| `{채널키}` | `led_a1=1` | 해당 채널 수동 목표 상태 (0/1, on/true 등) |
| `auto_{채널키}` | `auto_pump_a1=1` | 해당 채널 AUTO 여부 |
| `on_{채널키}` | `on_pump_a1=30` | ON 구간 **초** (최소 1) |
| `off_{채널키}` | `off_pump_a1=90` | OFF 구간 **초** (최소 1) |

불리언 값: `1`, `0`, `on`, `off`, `true`, `false` (대소문자 무시 일부).

## 아키텍처 원칙 (규칙·실행 분리) — **확정**

| 계층 | 역할 |
|------|------|
| **Node-RED(Pi)** | 스케줄·온도·AND/OR 등 **규칙 평가**, SQLite에 설정·이력 유지, 결과를 MQTT로 반영 |
| **Arduino** | **실행기**. 수신한 `cmd`(키=value)로 채널 출력·AUTO·주기 적용. **ruleEngine 트리는 펌웨어에 내리지 않음** |
| **펌웨어 한정** | 생명·안전용 **하드 가드**만 구현 — 예: 펌프 **최대 연속 가동 시간** 초과 시 강제 OFF, 향후 과열·인터록 등. 가드 파라미터·동작은 코드·본 문서에서 추적 |

네트워크 단절 시: 자동 제어는 Pi 쪽 규칙이 멈출 수 있으므로, **현장 안전은 펌웨어 가드**로 보완한다.

## 펌프 하드 가드·안티 쇼트사이클 (합의)

펌프 채널(`pump_*`)에만 적용. 수치(최대 연속 ON, 쿨다운 초, 최소 OFF 등)는 **펌웨어 상수**로 두고, 별도 표로 코드·본 문서에 맞춘다.

| 항목 | 합의 내용 |
|------|-----------|
| **상한 도달** | 해당 채널 **즉시 OFF** → **일정 시간 쿨다운** 경과 후에만 다시 ON 허용. 쿨다운 길이(초)는 상수로 정의 |
| **짧은 주기 반복** | 앞서 검토한 대로 **최소 OFF 간격·반복 억제** 룰 적용(구체 초는 상수·구현 시 확정) |
| **적용 범위** | **펌프 채널만** (LED/FAN 등에는 동일 상한 미적용) |
| **재부팅·전원** | **mx/mf 잔여 시간**은 EEPROM으로 복원. 연속 ON 카운터는 부팅 시 펌프 OFF라 **0부터**. 짧은 재시작은 EEPROM 잔여값으로 보수적 처리 |
| **`tele` 관측** | **`G:` 구간** — 형식은 §2.2 |
| **Pi와 이중 상한** | 동일 조건이 Node-RED에 있어도 **충돌 시 펌웨어 가드가 우선** |
| **MQTT 단절** | 단절 중에도 위 가드는 **로컬에서 동작**해야 함 — 시나리오별로 구현 후 점검 |
| **트립 후 복귀** | **자동 복귀**: 수동 리셋 없이, 쿨다운 종료 후 **기존 AUTO/주기 로직에 따라 재개** |

## 4. 확장 영역 (설정 탭·저장소) — **미구현 초안**

로드맵 요구: 채널별 자동/수동·수동 전환 시각 DB, 스케줄 ON/OFF vs 주기, Fan 온도 조건, 규칙 AND/OR.

### 4.1 MQTT 방향

| 옵션 | 설명 |
|------|------|
| **A** | 기존 `cmd`에만 토큰 추가 (Arduino 버퍼·파서 부담) |
| **B** | `cronusfarm/{DEVICE_ID}/cfg/get` · `.../cfg/set` 등 **설정 전용 토픽** + JSON 또는 줄 단위 |
| **C** | Node-RED만 DB·규칙 보관, Arduino에는 **승인된 최종 상태만** 기존 `cmd`로 전달 |

**확정**: **C** + 위 **아키텍처 원칙**(규칙은 Node-RED, Arduino는 실행기 + 하드 가드).

### 4.2 DB — **SQLite 스키마 v1 확정**

상세·DDL: `scripts/sql/cronusfarm_record_v1.sql`, 요약: `docs/cronusfarm_sqlite_schema.md`.

| 테이블 | 용도 |
|--------|------|
| `device` | 장치 마스터 (`device_id`) |
| `tele_sample` | MQTT `tele` 원문 |
| `tele_channel_fact` | S/A/T 파싱 채널별 스냅샷 |
| `mqtt_cmd_log` / `mqtt_status_log` | MQTT `cmd`·`status` 이력 |
| `pump_guard_event` | `G:` mx/mf 등 |
| `settings_kv` | 관제 UI 목표값·임계 등 키-값 |
| `manual_switch_event` | 수동 전환(향후 규칙 엔진과 연동) |
| `schedule_profile` / `alert_rule` | 스케줄·알림 JSON(추후 채움) |
| `sensor_reading` | pH·EC 등 센서 행(HTTP·ETL 적재) |

**수집 경로**: Node-RED(`flows_cronusfarm_mqtt.json`) → HTTP `scripts/cronusfarm_sqlite_bridge.py` → SQLite. 시계열 그래프는 **InfluxDB**(`tele` 측정, 채널·`guard_*` 필드 확장).

### 4.3 JSON 설정 스냅샷

머신 리더블 검증용 초안: [`schema/cronusfarm_cfg_snapshot.schema.json`](schema/cronusfarm_cfg_snapshot.schema.json)
